01  /  Understanding

Twenty-five years of trust. One more channel.

Rawafed Health International distributes medical equipment, rehabilitation and orthopaedic products, dental and consumer health brands across the Kingdom — from Riyadh, Al Khobar and Jeddah, to hospitals, clinics and, increasingly, directly to patients through rawafedhealth.com. 02  /  WooCommerce API audit — read this first

What your WooCommerce gives us. And what it doesn't.

We tested the live endpoints at rawafedhealth.com on 11 November 2026, as an outside client would. The verdict in one line: the catalogue and cart are ready for a mobile app today; customer accounts, payments, order history, wishlist and push are not exposed in any form an app can safely use. That gap is the single most important fact in this proposal, and it is why a companion WordPress plugin is in scope rather than an option.

Ready today

Catalogue, cart, checkout draft

The public Store API (/wc/store/v1) serves products, variations, attributes, categories, brands, reviews, coupons, shipping rates and the cart. It accepts a Cart-Token header instead of cookies, which is exactly what a headless mobile app needs. WPML answers in English or Arabic per request.

Works, with care

Payments & caching

Checkout creates the order and hands back a redirect URL for MyFatoorah, tabby or tamara — none of them are native-card gateways here. The app must open a secure in-app browser and catch the return. LiteSpeed Cache on the site must exclude /wp-json or the app will show stale stock.

Not available

Login, orders, wishlist, push

The Store API is unauthenticated by design. There is no login endpoint, no JWT plugin on the site, and the only authenticated API (/wc/v3) needs admin-level keys that must never ship inside an app. My Orders, addresses, YITH wishlist, Request-a-Quote, account deletion and push tokens have no mobile-usable endpoint at all.

Why this matters for the contract

An app built on the Store API alone can browse and fill a cart, and nothing else. Anyone who quotes you a "WooCommerce app" without server-side work is either planning to embed admin keys in the binary — a security failure that would expose every order and customer in your store — or planning a WebView. Three things therefore need to be agreed before kickoff:

  1. Install access. We deploy a small, open-source-licensed companion plugin ("RHI Mobile Bridge") on your WordPress, ideally on a staging copy first. It adds endpoints only; it changes nothing on the website.
  2. MyFatoorah account settings. Apple Pay and mada inside the app depend on those methods being enabled on your MyFatoorah merchant account. We will verify with them in week one.
  3. An SMS provider. OTP login on Saudi numbers needs a sender ID with Unifonic, Msegat or your existing provider. Account in your name; we integrate.

06  /  Architecture & stack

Your WooCommerce stays the only source of truth.

No second database, no sync jobs, no admin keys on the device. The app talks to WooCommerce's public Store API for everything public, and to the Bridge plugin — running inside your WordPress, authenticated per customer — for everything personal.

Mobile app

  • React Native with Expo, TypeScript, over-the-air updates for non-native changes
  • Store API client with Cart-Token sessions and local cart persistence
  • Secure token storage (Keychain / Keystore), biometric unlock
  • In-app secure browser sheet for payment with deep-link return
  • i18n with RTL layouts, Arabic default, English toggle
  • Firebase Analytics, Crashlytics, push via FCM / APNs

RHI Mobile Bridge — WordPress plugin

  • /rhi/v1/auth — OTP, email, Apple, Google; JWT access + refresh; cart merge on login
  • /rhi/v1/me — profile, addresses, orders, order timeline, re-order, returns
  • /rhi/v1/wishlist, /rhi/v1/quotes — over existing YITH data
  • /rhi/v1/search — name + SKU + brand, counts, both languages
  • /rhi/v1/devices — push tokens; hooks on woocommerce_order_status_*
  • Gateway webhook verification, rate limiting, audit log; no admin capabilities exposed

Existing store, untouched

  • WordPress 7.1 · WooCommerce 9.3 · WPML 5.2 — products, stock, prices, orders
  • Store API /wc/store/v1 — catalogue, cart, checkout
  • MyFatoorah v2, tabby, tamara — same merchant accounts, same settlement
  • YITH Wishlist and Request-a-Quote — same tables, same admin screens
  • LiteSpeed Cache — /wp-json excluded; Redis object cache if host permits
  • Website continues to work exactly as today
